# 农知行 · 自动部署操作手册

> 适用仓库：GitHub `liuyang582/nongzhixing`
> 部署目标：云服务器 `nongzhixing` systemd 服务
> 最后更新：2026-11-26

本手册覆盖：首次配置、日常自动/手动部署、本地一键部署、验证、回滚与故障排查。

> ⚠️ 本仓库为**公开仓库**。服务器 IP、SSH 私钥、数据库密码、演示账号密码等敏感信息不得写入任何受版本控制的文件，一律通过 GitHub Secrets 或本地未跟踪配置提供。

---

## 1. 快速开始（首次配置约 5 分钟）

- [ ] 确认服务器满足「3. 前置条件」
- [ ] 在仓库添加 3 个 Secrets：`NXZ_HOST`、`NXZ_SSH_USER`、`NXZ_SSH_KEY`（见 4.1）
- [ ] 确认阿里云安全组放行 SSH（见 4.2）
- [ ] Actions → **Deploy 农知行** → **Run workflow** 手动跑一次
- [ ] 查看日志，5 个步骤全部通过即完成

## 2. 整体架构

```
开发机 git push main
        │
        ▼
GitHub Actions（ubuntu-latest，云端）
  1. 检出代码
  2. 安装 Node.js 20（npm 缓存）
  3. 构建前端 qian：npm ci && npm run build
  4. 打包：hou/ + qian/dist/ + deploy/
  5. scp 制品 → ssh 执行 deploy/deploy-server.sh
        │
        ▼
云服务器（root）
  deploy-server.sh：
  1. rsync 同步后端代码（保留 .env / .venv / runtime）
  2. rsync 同步前端 dist
  3. pip install -r requirements.txt
  4. systemctl restart nongzhixing
  5. 轮询 /api/health 直到 200
        │
        ▼
Nginx 80 → 127.0.0.1:8000（uvicorn）
```

## 4. 首次配置

### 4.1 添加 GitHub Secrets

路径：**仓库 → Settings → Secrets and variables → Actions → New repository secret**

| Name | 说明 |
| --- | --- |
| `NXZ_HOST` | 服务器公网 IP 或域名（**不要写进仓库**） |
| `NXZ_SSH_USER` | 登录用户，通常为 `root` |
| `NXZ_SSH_KEY` | 部署用的 SSH **私钥全文**，含 `-----BEGIN ...` 与 `-----END ...` 两行 |

获取私钥内容（Git Bash）：

```bash
cat ~/.ssh/<部署私钥> | clip   # 复制到剪贴板后粘贴进 NXZ_SSH_KEY
```

注意事项：

- 必须包含首尾的 `-----BEGIN/END-----` 行，不要只复制中间内容；
- 私钥不能带口令（passphrase），否则 CI 无法非交互登录；
- 工作流会自动去除 Windows 的 `\r`，CRLF 私钥也能用；
- Secrets 加密存储，公开仓库下也不会以明文暴露，但**任何能修改本仓库的人**都能在 workflow 中读取，务必保护好仓库写权限。

### 4.2 放行网络

GitHub Actions 从云端公网访问服务器，需满足：

- 阿里云安全组允许来源访问 **22 端口**（可限制为 GitHub Actions 出口 IP 段，见 `https://api.github.com/meta` 的 `actions` 字段；该列表会变化）；
- 服务器 `sshd` 允许密钥登录；
- 若日志报「无法获取主机密钥」，基本就是安全组未放行。

## 5. 日常部署

### 5.1 自动部署的操作清单（每次照做）

自动部署由 GitHub 执行，但**操作人需要按下面三步手动操作**。

#### ① 部署前（本地，约 1 分钟）

```bash
git status                 # 确认没有遗漏或误改的文件
git add nongzhixing
git commit -m "feat: xxx"
git push origin main
```

检查项：

- [ ] 改动只涉及预期文件（不要误提交 `.env`、`deploy.local.ps1` 等被忽略文件）
- [ ] 首次使用已配置 `NXZ_HOST`、`NXZ_SSH_USER`、`NXZ_SSH_KEY` 三个 Secrets（见 4.1）
- [ ] 本机能正常访问 GitHub（需要时先开代理）

#### ② 部署中（浏览器观察，约 1 分钟）

1. 打开 <https://github.com/liuyang582/nongzhixing/actions>
2. 点击**最新一次**运行（核对运行编号和时间，不要看历史失败记录）
3. 依次展开 5 个步骤：检出代码 → 安装 Node.js → 构建前端 → 打包制品 → 上传并部署
4. 某步变红时：
   - 点开该步骤看日志；
   - 对照第 9 节「常见问题排查」处理；
   - 修复后点 **Re-run all jobs**，或重新推送。

> 判断标准：运行显示绿色 ✅，且「上传并部署」日志最后出现 `部署完成：<时间>`。

#### ③ 部署后（本机核对，约 30 秒）

在本机 Git Bash 执行（把 `<服务器IP>`、`<部署私钥>` 换成自己的）：

```bash
ssh -i ~/.ssh/<部署私钥> root@<服务器IP> '
  tail -3 /opt/nongzhixing/.deploy/deploy.log;
  stat -c "%y" /opt/nongzhixing/hou/app/main.py;
  systemctl is-active nongzhixing;
  curl -s -o /dev/null -w "health %{http_code}\n" http://127.0.0.1/api/health
'
```

通过标准：

- [ ] `deploy.log` 最后一行时间 = **本次运行的时间**，且包含 `部署完成`
- [ ] `main.py` 的修改时间是**本次部署时间**
- [ ] 服务输出 `active`
- [ ] `health 200`

最后用浏览器打开 `http://<服务器IP>/`，页面能正常加载即可。

> **不要在服务器上手动改代码**：部署脚本用 `rsync --delete` 覆盖 `hou/` 和 `qian/dist/`，手改内容下次部署会被清除。服务器上的 `hou/.env`、`hou/.venv`、`hou/runtime` 会被保留。

### 5.2 自动触发规则

推送到 `main`，且改动命中以下路径时自动触发：

- `nongzhixing/**`
- `.github/workflows/deploy.yml`

同一时间只允许一个部署任务（`concurrency: deploy-nongzhixing`），后触发的会排队而非中断。

### 5.3 手动触发

**Actions → Deploy 农知行 → Run workflow → 选择 main → Run。**

适用于：重跑失败任务、在不改代码的情况下重新部署、仅回滚后验证。

### 5.4 本地一键部署（备用）

本地网络受限或 GitHub Actions 不可用时使用，流程等价：

```powershell
# 双击 deploy.cmd，或
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy.ps1
```

脚本从本地未跟踪的 `deploy.local.ps1` 读取服务器信息（该文件已被 `.gitignore` 忽略）：

```powershell
$server  = '<服务器 IP 或域名>'
$sshUser = 'root'
$sshKey  = Join-Path $HOME '.ssh/<部署私钥>'
```

也可用环境变量覆盖：`NXZ_SERVER`、`NXZ_SSH_USER`、`NXZ_SSH_KEY`。

可选参数：`-SkipBuild`（跳过前端构建，仅部署已有 `qian/dist`）、`-SkipInstall`（跳过 `npm install`）。

## 6. 部署流程详解

### 6.1 GitHub Actions（`.github/workflows/deploy.yml`）

| 步骤 | 动作 |
| --- | --- |
| 检出代码 | `actions/checkout@v4` |
| 安装 Node.js | `actions/setup-node@v4`，Node 20，缓存 `qian/package-lock.json` |
| 构建前端 | `npm ci --no-audit --no-fund && npm run build`，校验 `dist/index.html` |
| 打包 | tar 排除 `.venv/.runtime/.env/.idea/__pycache__/*.log/*.tsbuildinfo` |
| 上传部署 | 写入临时私钥 → `ssh-keyscan` 校验主机 → `scp` → `ssh` 执行服务器脚本 |

### 6.2 服务器脚本（`deploy/deploy-server.sh`）

| 步骤 | 动作 |
| --- | --- |
| 1/5 | `rsync -a --delete` 同步 `hou/`，**保留** `.env`、`.venv/`、`runtime/`、`__pycache__/` |
| 2/5 | `rsync -a --delete` 同步 `qian/dist/` |
| 3/5 | `hou/.venv/bin/pip install -r requirements.txt` |
| 4/5 | `systemctl restart nongzhixing` |
| 5/5 | 轮询 `http://127.0.0.1/api/health`（最多 15 次 × 2s），并检查服务 active |

日志：服务器 `/opt/nongzhixing/.deploy/deploy.log`。

## 7. 验证

1. **Actions**：本次运行全部步骤为绿色；
2. **站点**：浏览器访问 `http://<服务器IP>/` 返回首页；
3. **健康检查**：`curl http://<服务器IP>/api/health` 返回 200 且数据库状态正常；
4. **服务**：`systemctl status nongzhixing` 为 active；
5. **日志**：服务器 `tail -f /opt/nongzhixing/.deploy/deploy.log`，应看到「部署完成」。

## 8. 回滚

部署失败**不会自动回滚**（代码已同步）。回滚方式：

### 方式 A：Git 回滚（推荐）

```bash
git log --oneline          # 找到上一个正常版本
git revert <坏提交>        # 或 git revert --no-commit <范围>
git push origin main       # 触发一次新的自动部署
```

### 方式 B：本地重新部署旧版本

```bash
git checkout <正常版本的 commit>
deploy.cmd                 # 本地一键部署
git checkout main
```

回滚后同样要观察 Actions 与 `/api/health`。

## 9. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 日志提示「缺少仓库 Secrets」 | 未配置 `NXZ_HOST/NXZ_SSH_USER/NXZ_SSH_KEY` | 按 4.1 添加后重跑 |
| 「hostname contains invalid characters」 | `NXZ_HOST` 含空格/换行/`http://`/端口等多余字符（粘贴时带入） | 重新录入 `NXZ_HOST`，只填 IP 或域名（工作流会自动去首尾空白并校验） |
| 「NXZ_HOST 含非法字符」 | 同上，校验未通过 | 同上 |
| 「无法获取主机密钥」 | 安全组/防火墙未放行 22；IP 填错 | 检查安全组与 `NXZ_HOST` |
| `Permission denied (publickey)` | 私钥内容不完整、带口令、或用错密钥 | 重新粘贴完整私钥，确认无 passphrase |
| `npm ci` 失败 | lock 文件与 package.json 不一致、Node 版本不符 | 本地 `npm install` 后提交新 lock；确认 Node 20 |
| 健康检查未通过 | 后端启动失败、数据库/Redis 未就绪、`.env` 错误 | 服务器 `journalctl -u nongzhixing -n 100` |
| 改了文件但没触发 | 改动不在 `nongzhixing/**` 或 workflow 内 | 手动 Run workflow，或调整 `paths` |
| `rsync: command not found` | 服务器未安装 rsync | `dnf install -y rsync` |
| `服务器 venv 不存在` | `/opt/nongzhixing/hou/.venv` 缺失 | 按内部部署流程重建 venv |
| 部署卡住/超时 | 服务器资源不足或网络抖动 | 重跑；必要时本地部署 |

## 10. 安全注意事项

- **公开仓库**：任何写入 Git 的服务器 IP、私钥、密码都会永久留在历史中，删掉也可能被缓存/索引。敏感信息只放 Secrets 或本地忽略文件。
- 当前使用 **root 私钥** 存于 Secrets，权限较大。若需加固，建议创建专用部署用户，并在 `authorized_keys` 限制只允许执行部署命令。
- **演示账号密码**：源码默认值仅供本地演示，生产环境必须在服务器 `.env` 设置强密码（`DEMO_PASSWORD`）或关闭播种（`SEED_DEMO=false`），修改后重启服务；已有用户的密码不会自动更新，需在后台重置。
- 不要在 workflow 中使用 `pull_request_target` 拉取并执行不可信代码；本流程仅响应 `push` 到 `main`。
- 定期轮换部署密钥，并在 GitHub Secrets 中同步更新。
