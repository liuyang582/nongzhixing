# 农知行微信小程序

现有账号登录后进入四栏工作台：首页、生产管理、AI 助手、我的。地块绘制、复杂边界修改和 GeoJSON/SHP 导入继续在 PC；小程序支持地块普通档案新增编辑及查看已登记边界。

## 已接入的日常业务

- 首页：授权范围内统计、库存、待出库订单和近期记录。
- 生产管理：地块地图，元数据驱动的业务台账查询/筛选/分页/新增/编辑/删除，生长批次关联、人工环境记录、任务状态与执行结果。
- AI 助手：问答、种植及产销分析、拍照或选择照片、关联地块/生长批次诊断、历史回答、人工确认安排任务、驳回建议。照片读取后编码发送现有模型接口，Key 始终在后端。
- 经营：环境阈值规则启停，关联采收登记及一次入库，库存销售订单预占/出库/取消，溯源公开开关与二维码，年度及月度成本销售汇总。
- 工具：农技资料、天气、待办、PDF/Excel 报表下载预览、附件上传下载、修改密码；管理员账号新增/启停和审计列表。
- 后端权限、事务、版本冲突和不可重复入库约束继续生效。所有操作提交失败均显示后端错误，不自动重复提交 AI、库存或采收操作。

## 使用

1. 保持原项目 8000 后端、5173 前端运行。在微信开发者工具中打开本目录，点击“编译”；登录后显示底部四个入口，不再只有地块列表。如果保留了旧编译路径，请切换到普通编译。
2. 开发工具本地调试地址在 `miniprogram/utils/config.js`，默认 `http://127.0.0.1:5173/api`，通过现有 Vite 代理调用 FastAPI。已有私有项目配置 `urlCheck:false` 本轮没有更改。
3. 输入现有平台账号密码。种植户查看所属经营主体，监管员查看辖区；管理员没有地块权限。权限最终由后端控制。
4. 地块页可搜索、下拉刷新、加载更多。点卡片查看地图、档案和按 `plot_id` 关联的生长/任务记录。

真机不能使用 `127.0.0.1`。真机体验/发布需要可访问后端地址，并按微信要求设置 request 合法域名、HTTPS 和相关隐私声明。不要把模型 Key、数据库密码或微信 AppSecret 放入小程序。API Token 在本地存储，退出登录或会话失效时清除；不保存账号密码。

## 地图说明

使用小程序原生 map 组件，不加载网页高德 JS SDK，因此现有网页高德和模型配置无需修改。不引入云数据库或云函数；AI 用户点击提交后调用现有 FastAPI 模型接口。
数据库边界与位置使用 WGS84，显示时复用 PC 的近似 GCJ-02 转换；不回写坐标、不修改原边界。支持 Polygon / MultiPolygon 的外环；孔洞不渲染，页面明确说明。无有效边界和位置时展示缺失状态，不生成演示坐标。卫星按钮仅切换底图，不代表遥感分析或真实采集。

## 验证及限制

- `node xcx/tests/acceptance.cjs`：坐标、无定位、MultiPolygon、无效边界、监管员例外权限、档案关联隔离测试通过；真实现有后端 farmer/regulator 地块查询各 2 条，admin 返回 403。
- 新代码 `node --check` 通过；JSON 和 WXML 结构检查通过（`hou/.venv/Scripts/python.exe xcx/tests/verify_markup.py`）。
- 初版真实接口验证仅登录/查询；扩展写入验收使用独立 SQLite，不涉及现有 MySQL。`node xcx/tests/workbench.cjs` 共 28 项通过，覆盖表单、AI 确认、任务、采收入库、订单、服务页面、报表文件落盘与附件字节一致性。需要先运行 `hou/scripts/browser_acceptance_server.py` 创建隔离服务和临时会话；测试脚本断言服务使用测试桩。
- 使用已安装微信开发者工具附带的 `wcc.exe` 编译全部 10 个页面、`wcsc.exe` 编译全局样式，全部通过。修复了 `requiredPrivateInfos` 不支持 openLocation，以及条件表达式误用 HTML 转义操作符的问题。
- 尚未确认完整模拟器运行、原生地图呈现与真机体验：工具 CLI 提示“服务端口已关闭”，无法自动获取模拟器结果。WXML 编译通过不等同于完整业务验收。
- 写入测试运行页面 JS 处理器及真实隔离 HTTP 接口，模拟微信宿主 API，不是实体手机触控验收。天气和 AI 为明确标注的测试桩，本轮未重新调用外部模型。拍照、选文件、地图呈现、文件打开/分享等系统 UI 仍需在开发者工具或实体设备验证。
- 复杂地图编辑、完整 PC 分析图表、管理员密码重置及打印功能仍保留 PC；小程序不是逐项复制 PC。二维码仍沿用原后端的本机 PC 地址，实体手机扫码需要另行配置可访问地址。

原入口、样式和页面备份于 `template-backup`；原云函数、项目 AppID 和项目配置保留。恢复时复制备份 app 三文件及 pages 回 miniprogram。`build_nzx.py`、`expand_workbench.py`、`add_services.py`、`finalize_workbench.py` 是一次性生成/修正脚本，当前以 miniprogram 源码为准，不要在手工改页面后重跑这些脚本，以免覆盖修改。
