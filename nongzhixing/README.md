## 启动

先启动本地 MySQL，再双击项目根目录的 `启动项目.cmd`。脚本会使用 `hou/runtime/redis-install.txt` 中记录的本机安装位置启动 Redis；若安装目录变化，需要更新该路径。
浏览器访问 http://127.0.0.1:5173 ，后端接口文档 http://127.0.0.1:8000/docs 。

初始账号：`farmer`、`regulator`、`admin`。初始化密码由 `DEMO_PASSWORD` 决定，默认 `demo123`；修改环境变量不会重置已建立账号的密码。
Redis 使用 DB1；数据由后端写入，无需手动创建 Key。

也可分别在两个终端启动：

```powershell
# 在 hou 目录
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 在 qian 目录
npm.cmd run dev -- --strictPort
```

首次缺少依赖时：在 hou 目录用 Python 3.11+ 创建 `.venv`，执行 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`；在 qian 目录执行 `npm.cmd install`。

## 本机上线部署（无域名，局域网访问）

不购买域名时，也可以在本机以生产模式运行：前端构建为静态文件，由 FastAPI 同源托管，只占用一个端口（默认 8080），同一局域网的手机或电脑用 `http://电脑IP:8080` 访问。开发模式（5173 + 8000 + 热更新）不受影响。

### 一键启动

1. 确认本地 MySQL（phpstudy）已启动；Redis 可由脚本按 `hou/runtime/redis-install.txt` 自动拉起。
2. 双击 `启动上线版.cmd`。脚本会：
   - 检查 MySQL 3306、Redis 6379；
   - 当 `qian/src`、`index.html` 或 `package.json` 比 `dist` 新时自动执行 `npm run build`（也可运行 `powershell -File .\启动上线版.ps1 -Rebuild` 强制构建）；
   - 以 `uvicorn app.serve:app --host 0.0.0.0 --port 8080` 隐藏启动，日志写入 `hou/runtime/backend-prod-*.log`；
   - 输出本机与局域网访问地址。
3. 首次跨设备访问前，右键 `放行局域网端口.cmd` →「以管理员身份运行」，放行 TCP 8080。**不要**放行 3306 或 6379。

访问地址：

- 本机：`http://127.0.0.1:8080`
- 局域网：`http://<电脑局域网IP>:8080`（脚本会自动打印，例如 `http://172.20.10.4:8080`）
- 接口文档：`http://127.0.0.1:8080/docs`

### 停止 / 开机自启 / 备份

- 停止：双击 `停止上线版.cmd`，按 `hou/runtime/production.pid` 结束整个进程树。
- 开机自启：双击 `开机自启.cmd` 注册登录时任务；取消执行 `powershell -ExecutionPolicy Bypass -File .\开机自启.ps1 -Remove`。
- 备份：运行 `备份数据.ps1`（需输入 MySQL 密码），导出到 `backups/<时间>/`：数据库 SQL、`hou/runtime/uploads`、`.jwt-secret`、`.env`。

### 上线相关改动

- 新增 `hou/app/serve.py`：托管 `qian/dist`，保留 `/api` 与 `/_AMapService`，为 `/trace/xxx` 等前端路由做 SPA 回退；未知 `/api` 路径仍返回 JSON 404。原开发入口 `app.main:app` 不变。
- 溯源二维码不再写死 `127.0.0.1:5173`，默认按访问者当前地址生成；也可在 `hou/.env` 设置 `PUBLIC_BASE_URL` 固定二维码地址。
- 前端接口原本使用相对路径 `/api`，同源部署无需改代码。

### 注意事项

- 无域名且未备案时外网无法直接访问，只能在同一局域网或手机热点内使用。需要公网访问时，应使用已备案域名 + HTTPS 的云服务器，或临时使用内网穿透工具（仅演示用）。
- **演示账号密码**：`farmer` / `regulator` / `admin` 默认 `demo123`，且本项目按需求以明文保存密码。允许局域网访问前请在系统内修改密码，不要把服务暴露到不可信网络。
- **MySQL 监听地址**：phpstudy 的 MySQL 当前监听 `0.0.0.0:3306`。请确保 Windows 防火墙未放行 3306，或把 MySQL 改为仅监听 `127.0.0.1`。
- **高德地图 Key**：JS API Key 需要配置域名白名单；通过局域网 IP 访问时可能报 `INVALID_USER_DOMAIN`。演示时可将该 Key 白名单设为「不限制」，或使用已加入白名单的域名/`localhost` 访问。
- **微信小程序**：真机调试时把 `xcx/miniprogram/utils/config.js` 的地址改为 `http://<电脑IP>:8080/api`，并在开发者工具中勾选「不校验合法域名」；正式发布仍要求 HTTPS + 已备案域名。
- 局域网 IP 由路由器 DHCP 分配，重启后可能变化；需要固定地址时在路由器中为这台电脑绑定静态 IP。
- 上传附件在 `hou/runtime/uploads`，数据库在 MySQL `nongzhixing` 库，二者必须一起备份。

## 核心流程演示

1. 用合作社账号登录，点击“种植管理流程”。
2. 新建地块，填写名称、作物和实际经纬度。已有地块可点击“补充地块定位”。边界在 GIS 模块绘制。
3. 新增生长记录：填写种植批次、播种日期、实际阶段和观察记录。目录内原有无关联编号的历史记录不会自动串入新流程。
4. 在“天气与环境”查询该地块天气，并录入田间温湿度；标明人工记录、模拟器或传感器来源。天气不能替代土壤实测。
5. 在“AI分析与确认”选择生长记录，上传 JPG/PNG/WebP 图片，描述异常。接口保存照片、地块、生长、环境及天气快照，并实际调用配置的千问模型。
6. 阅读分析，点击“人工确认并安排任务”，填写执行人、日期及确认意见；也可以驳回，驳回不生成任务。
7. 在“农事任务与反馈”开始任务，填写现场执行结果后完成；可返回查看原始分析。重复确认不会重复生成任务。

真实模型接口或天气服务失败时显示错误/资料缺失，不返回伪造的分析或天气。AI仅辅助初筛，不自动施药、控制设备或执行农资扣减。

`hou/tests/fixtures/leaf-demo.png` 是人工绘制的联调示意图，不是真实病叶照片。演示时必须说明这一点；实际病虫害识别效果需要真实样本评测。

## 内部 RAG 知识库（2026-11-05）

- 语料：`hou/app/data/agri_knowledge_v1.jsonl`（96 条，A–G 七类），服务启动时按 `doc_id` 幂等导入 `nx_knowledge_docs`；可用 `hou/.env` 的 `RAG_CORPUS_PATH` 指向自定义 JSONL。
- 建档：Web 与小程序「惠农服务 → 知识库与农技问答」。所有登录角色可浏览、检索；仅 `admin` 可新增、修改、删除和导出，操作写入审计日志。
- 检索：本地纯 Python BM25（中文单字 + 重叠二元组，标题/关键词/问法加权，作物与地区元数据过滤），不依赖外部向量库或新增依赖。
- AI：`/api/ai/analyze` 调用模型前检索前 5 条知识，回答按 `[编号]` 引用，结果 `result.citations` 返回编号、标题、来源、时效、风险与片段；无命中时明确提示知识不足。
- 接口：`GET /api/knowledge/docs`、`GET /api/knowledge/docs/{id}`、`POST /api/knowledge/search`、`POST/PUT/DELETE /api/knowledge/docs`、`POST /api/knowledge/seed`、`GET /api/knowledge/export/csv`。
- 边界：检索片段只作参考依据，不构成用药处方；时效性资料需核对最新公告。

## 新增答辩功能（2026-10-02）

- 生产与经营分析：地块生长时间轴、批次筛选；按作物及阶段配置环境阈值，新增观测自动产生预警，同一规则/指标未关闭时不重复生成。
- 成本与销售收益：按年度汇总农资、农机与其他支出，统计已出库销售；可选包含演示数据、月度图表、地块及每亩差额、未关联金额；支持经营 Excel/PDF 导出。
- 采收与溯源：选择已关联地块的生长批次登记实收重量，一次入库并生成二维码；默认未公开，用户确认后公开生产摘要，已入库采收不可修改或删除。公开入口 `/trace/随机码` 不要求登录。
- 农技资料：番茄、黄瓜、水稻的巡检提纲与官方资料链接，注明年份、地域和适用范围；不包含未经核验的药剂处方。
- 市场分析：同品类/地区/等级/报价口径的登记走势，报价来源与数量×单价情景测算；不是实时行情或价格预测。
- 工作工具：Excel 与中文 PDF 台账导出、待办汇总、修改密码、管理员重置密码。密码变更后旧令牌失效；账号密码不会因升级被修改。

演示顺序：种植管理流程 → 地块时间轴 → 配置阈值并新增环境观测 → 告警中心处理 → 采收与溯源 → 库存销售 → 成本收益 → 报表。
溯源二维码按访问者当前地址自动生成（可用 `PUBLIC_BASE_URL` 固定），本机和局域网扫码均指向对应服务地址。`outputs` 中的示例文件来自合成演示数据。
升级启动时仅增加 `nx_users.token_version` 字段及 `nx_traces` 表，保留现有业务数据。新增后端逻辑在 `hou/app/features.py`，页面在 `qian/src/views/DefenseWorkbench.vue`。

## 高德地图接入

GIS 地块与辖区地图已改为高德 JS API 2.0，支持地址搜索、标准/卫星底图、新地块绘制与顶点调整、信息卡、GeoJSON/SHP ZIP 导入。
`hou/.env` 配置 AMAP_KEY 与 AMAP_SECURITY_CODE；前端仅取得 JS Key，安全密钥由 FastAPI 的 `/_AMapService` 固定路径代理使用。开发时 Vite 代理该路径；部署时也须转发一级路由 `/_AMapService` 到后端，不能删除高德署名。
已有 WGS84 边界保留，显示时近似转换为 GCJ-02；手绘边界近似转换回 WGS84 后保存，定位可用于现有天气模块。此转换与面积仅供农业管理参考，不是法定测绘成果。
代理只允许地理编码、地点搜索及地图样式路径，固定上游域名，覆盖请求中的 Key/安全密钥，并通过 Redis 限流。地图与搜索需要联网及有效的高德账号授权。
高德官方安全代理说明：https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode
坐标回归测试：在 qian 目录执行 `node --test tests/amap-coordinates.test.mjs`。
账号密码按用户要求改为明文存储（2026-10-02）。新建账号、修改和重置密码均保存原文；现有演示账号仅在验证已知密码正确后迁移。其他旧哈希在成功登录后迁移，不重置未知密码。数据库中的 password 字段可直接读取密码，论文须按实际存储方式描述。
