## 五、数据库表说明

所有表统一使用 `nx_` 前缀，定义在 `app/core.py`。

| 表名 | ORM 类 | 用途 |
|---|---|---|
| `nx_users` | `User` | 账号、角色、组织、辖区、启用状态、令牌版本 |
| `nx_records` | `Record` | 全部业务台账（地块/生长/任务/环境/市场等），JSON 存业务字段 |
| `nx_stocks` | `Stock` | 采收入库后的库存批次、总库存与预占量 |
| `nx_orders` | `Order` | 销售订单、客户、数量、单价、出库状态 |
| `nx_audits` | `Audit` | 登录、增删改、导出、AI 确认等操作日志 |
| `nx_ai_jobs` | `AIJob` | AI 问题、状态、输入快照、回答、流程步骤与关联任务 |
| `nx_attachments` | `Attachment` | 附件元数据与随机存储文件名 |
| `nx_traces` | `Trace` | 溯源码、公开状态、生产摘要快照 |

设计要点：

- **通用记录 + JSON**：一个 `nx_records` 表承载 26 个模块，字段结构由 `catalog.py` 定义（`features.py` 追加 `expenses`），避免为每个业务建表；知识库因全局共享单独使用 `nx_knowledge_docs`。
- **数据隔离**：记录、库存、订单、AI 任务、附件、溯源都带 `org` / `district` 字段，由 `scope()` 按角色过滤。
- **乐观锁**：`Record.version` 每次修改加 1，前端提交旧版本时返回 409。
- **演示标记**：`demo` 字段区分系统样本与用户真实录入，核算和导出时可选择是否包含。
- **冻结快照**：溯源 `snapshot` 在入库时生成，后续台账修改不会影响已公开内容。

## 六、启动流程与关键链路

### 6.1 启动时序（`main.py · lifespan`）

```text
uvicorn app.main:app
  → 导入 core.py：读取 hou/.env，生成/读取 JWT 密钥，创建数据库引擎
  → 创建 FastAPI 实例
  → lifespan 启动：
      1. Base.metadata.create_all(engine)      自动建表
      2. features.migrate()                    增量迁移（token_version 列）
      3. seed(db)                              首次启动写入三个演示账号与样本数据
      4. Argon2id 演示密码迁移为明文
      5. 把“分析中”的 AI 任务标记为“已中断”
  → install_features(app, globals())           注册扩展业务接口
  → install_amap(app, current_user, cache)     注册高德配置与代理接口
  → 等待请求
  → 关闭时 await cache.aclose()                释放 Redis
```

### 6.2 一次登录请求的链路

```text
POST /api/auth/login
  → Redis 按 IP 限流（每分钟 20 次）
  → 查询 nx_users
  → passwords.verify()：明文 constant-time 比较 / 旧 Argon2id 校验
  → 旧哈希登录成功后迁移为明文
  → jwt.encode({sub, ver, exp}) 签发 8 小时令牌
  → 写入 nx_audits 审计
```

### 6.3 受保护接口的鉴权链路

```text
Authorization: Bearer <token>
  → current_user() 解码 JWT、校验签名与过期时间
  → 查询用户，校验 active 与 token_version
  → scope(stmt, model, user) 追加 org / district 条件
  → authorize(module, user, write) 校验模块角色权限
```

### 6.4 AI 工作流（`ai.py`）

```text
START → prepare（读取授权数据、检查资料）
      → analyze（千问多模态，astream 流式拼接）
      → needs_review：
          diagnosis / farm / planting / market → review（待人工确认）
          chat                                  → done（仅供参考）
      → END
```

人工确认后才由 `main.confirm()` 生成 `tasks` 记录，并在任务 `data.ai_job_id` 中保留来源；重复确认由条件更新拦截。

### 6.5 高德地图链路

```text
前端 loadAMap()
  → GET /api/amap/config                   取得 JS Key 与 /_AMapService
  → 设置 window._AMapSecurityConfig.serviceHost
  → 加载 https://webapi.amap.com/maps?v=2.0&key=...
  → SDK 的 REST 请求发往同源 /_AMapService/...
  → Vite / 部署环境转发到 FastAPI
  → amap.proxy()：白名单校验 → Redis 限流 → 附加 key + jscode
  → 转发 restapi.amap.com / webapi.amap.com
  → 原样返回 JSON / JSONP
```

安全密钥只保存在后端 `.env` 中，前端只能拿到 JS Key。

### 6.6 环境预警链路

```text
新增/修改 environment 记录
  → main.create_record / edit_record
  → validate_data() 校验
  → record_event() 写 Redis 最新值与事件流
  → features.evaluate()
      → 匹配地块、作物、生育阶段的启用规则
      → 逐项比较温度/湿度/土壤湿度
      → 同规则同指标未关闭时不重复生成
      → 生成 alerts 记录并写审计
```
